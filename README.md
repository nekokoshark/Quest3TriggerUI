# Quest3TriggerUI

为 **Virt-A-Mate 1.22.0.12** 在 **Quest 3（及 OpenVR/PCVR）** 下提供完整 VR 原生交互的 BepInEx 插件：VR 虚拟键盘 + 拼音输入法、径向快捷菜单、VR 预设/文件浏览器、原生对话框接管、包管理器封禁与卡顿缓解、物理降载档位与头发手动调试等。

## 功能一览

- **VR 虚拟键盘**：右手食指扳机+握把组合键呼出；世界空间 UI，可直接在 VR 里打字
- **离线中文拼音输入法**：rime-ice/雾凇拼音词典本地化——全拼、首字母简拼、模糊/前缀联想、词组补全、分次提交整句、**用户词频记忆**（`[IME] Learning` 开关）
- **径向快捷菜单**：右手食指长按呼出，物理降载/待机/重置等快捷动作
- **VR 预设浏览器**：接管 VaM 原生皮肤/外观/头发/服装/替换等全部文件对话框，var 包内容合并视图、启动预热防首开卡顿；标签页**视图状态持久化**（同地址标签共存、滚动/搜索/排序重开保持）；右上角**目标人物下拉**——预设可直接改加载到场景里其他 Person（含被关闭的）
- **预设部件化**：服装/皮肤/头发/眼睛四区块独立存取——人物预设可当部件库直接"拆用"（只换发型/只换肤/只换装/只换眼），当前部件也可写回任意本地人物预设；含 VaM 原生没有的眼睛预设系统（irises/sclera/lacrimals + 原生缩略图）
- **UIAssist 预设坞/收藏栏**：服装编辑器左右双栏缩略图即点即换；左侧预设坞五标签（替换/外观/发型/服装/皮肤）「新增」按标签开对应目录批量收藏；缩略图**拖拽重排**、跨标签拖放收藏、悬停翻页
- **VR 拍照机位**：多机位 VR 相机拍摄，缩略图、场景持久化、前后跳切
- **音频跟随**：VaM VR 音频自动跟随 Windows 默认输出设备切换，无需手动改路由
- **场景加载加速**：headless 菜单期预热（形变库/编目初始化 + 原子克隆池），加载窗口内选择器重建合并，大场景冷载 ~190s→~110-130s
- **包管理器封禁**：默认屏蔽原生包管理器入口（VaM 包扫描+缩略图解码是主要卡顿源），`[Browser] BlockPackageManager` 可关
- **物理降载档位 + 手动头发调试**：快捷降载，或逐片选中头发实时调 curl/density/模拟/碰撞
- **热重载架构**：HotLoader 常驻 + payload 字节加载，替换 payload 文件即热更新，无需重启 VaM
- **资源生命周期管理**：贴图解码在途字节预算（随可用内存/提交余量自动收紧）、同基底衣发跨预设复用、孤儿贴图来源追踪驱逐、预设清理事务化——连续换装不再把显存和提交一步步顶死

## 最新更新

> 每次发布在此追加最新一版的说明；完整历史见 Releases。

### v4.6.235 —— 资源生命周期重构（2026-09-25)

VaM 连续加载人物预设时，显存谷底逐次抬高（实测 9 次加载净涨 ~1.6GB)，且解码洪峰会把整机提交顶到上限导致进程直接死亡。本版本把内存管理从"定时清扫"重构为**事务化生命周期**：

- **贴图解码准入预算**：缓存查询后按预计在途字节放行，默认 2GiB，随可用物理内存与**系统提交余量**（防 OOM 的第二道闸）自动收紧到 256MiB 下限；排队/解码/待上传全程记账，超预算的单张大图仍可通行不死锁；已证实失效的原生请求在解码前直接淘汰
- **同基底衣发实例复用**：新预设仍点名要、且已就绪的服装/发型在原生 Reset 期间临时保留实例，免去销毁→重建→重解码→重上传的整轮开销；参数/物理恢复完整走原生路径
- **bump→法线三行转换**：原生为整幅图分配 heightmap（4K 图约 268MB 瞬时分配），改为 3 行滑动窗口（约 48KB)，输出字节布局与原生完全一致
- **清理事务化**：外观/服装/发型预设加载各自开事务，**仅成功提交后才调度清理**（失败/被新加载取代的事务自动作废）；清理等待图片队列排空与角色加载标记完成，加载中的部件自动延后补网
- **孤儿贴图来源追踪**：在原生回调完成前验明请求血统——仅角色/材质原生回调产生的贴图进入驱逐候选，UI/预载/第三方插件请求永不误伤；闲置贴图设 512MiB 软预算，超线按最老优先解除缓存所有权（不直接 Destroy，由 UnloadUnusedAssets 判活）
- **清理合并**：原生 MemoryOptimizer 已发起且覆盖全部释放请求的扫描直接复用，避免重复的全量资产爬取卡顿

以上全部经定向测试（46 项新增 + 77 项回归）与原生 IL 锚点校验，各模块独立配置开关、fail-closed 回退。**长期内存收益需实测验证**——这解决的是"越换越涨"的爬坡问题，不是降低 VaM 基础占用。

### 自上个发布版（v4.6.196）以来的累计变更

- **双手操作修复**：左右扳机各绑定自己的光标——右扳机不再抓走左手光标下的收藏槽位；左扳机获得对称的拖拽/点击能力；拖拽全程锁定防误开径向菜单
- **预设收藏栏扩容与提速**：7×8 每页 56 项、卡片复用、缩略图分帧泵入；「删除」改点按模式（再点取消收藏，拖出不再误删）
- **预设路径跟随**：游戏内移动/重命名预设后收藏栏自动同步；保存/改名输入框隐藏 `Preset_`/`.vap` 技术前缀
- **录制崩溃自愈**：闪退/热载后残留的录制器会被自动回收并封盘 WAV 头，录制文件不再无限增长

## 构建

需要本机 VaM 1.22.0.12 安装（引用 `VaM_Data\Managed` 下的 Assembly-CSharp / UnityEngine 等）与 BepInEx 5.x 引用集。参照 `tools/build/build.example.rsp` 把 `F:\vam1.22.0.12` 路径替换为本机路径，然后：

```
csc.exe -noconfig @build.rsp
```

产出 payload dll 用 `src/PUBLISH_HOT_UPDATE.ps1` 发布到
`BepInEx\plugins\Quest3TriggerUI\Quest3TriggerUI.payload.dll.disabled` 即热载生效。

> ⚠️ **热载约定**：每次构建的 `/out` 程序集名必须唯一（如 `Quest3TriggerUI_pHHMMSS.dll`）。同名程序集字节加载时，方法内对其他类型的引用会绑定到首个同名程序集，导致"改了代码运行无反应"。
